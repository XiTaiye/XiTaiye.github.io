画完的流程图再打开是空白：BPMN XML 被 XSS 清洗器静默剥空记

关键词： Flowable 8 工作流设计器 · @XssIgnore · Jsoup Safelist

现象一句话：流程设计器里画完图、点保存提示创建成功，回到「模型设计」列表再点「设计」，画布一片空白，什么图都出不来。

1. 现象与直觉误区

第一反应通常会怀疑前端：

  • 是不是设计器组件没挂载、importXML 时机不对？
  • 是不是 keep-alive 缓存了旧实例？

5. 解决方案

5.1 采用：方法级 @XssIgnore

按官方点位在 Boot 工程补齐 5 处（每处一个 import + 一个注解）：

@XssIgnore 的 value 是 String[]，所以还有更精准的进阶写法——只豁免 XML 字段，其余字段照洗：

我这里选择留空以与官方完全一致（空 value = 本次请求所有字段只 trim 不清洗），将来跨工程同步不会产生差异。

5.2 不采用：往 skip-url 加 /workflow/**

能解决问题，改动也最小，但它是按 URL 划一片免检区：detail / list / remove / 分类 / 按钮 / 主题 / 抄送……所有接口的所有字段一起失去保护，其中大部分接口根本不需要承载标记语言。豁免面远超必要面。

@XssIgnore 是按接口方法精确点豁免，两者比较：

维度 @XssIgnore xss.skip-url
粒度 方法级（可细到字段） URL 前缀级
改动位置 代码（随插件走） 配置文件
是否影响其它接口 否 是，整片放行
与官方插件一致 一致 不一致
换环境会不会漏配 不会（在代码里） 会（yml / Nacos 各有一份）

5.3 一个容易踩的隐蔽前提

xssConfiguration 注册拦截器时是这样的：

问题出在拦截器的注册范围：它只挂在 block-url 与 skip-url 覆盖的路径上。默认 block-url: /** 时一切正常，但一旦你把 block-url 改成白名单式的小范围，落在它外面的接口就会出现一种诡异组合：

  • 清洗器依然会洗（它挂在 Jackson 上，不看路径），
  • XssInterceptor 却不会为该请求设置 XssHolder，
  • 于是 @XssIgnore 形同失效。

调 XSS 配置时请一并检查 block-url，别只盯 skip-url。

6. 验证

6.1 数据层

重画一张图保存，然后：

判据很简单：

  • first_lt 必须 = 1（首字符就是 <）
  • len_xml 应该上万，而不是几百

只要 first_lt = 0，就是还在被洗。

6.2 界面层

模型设计列表 → 点「设计」→ 画布应直接呈现上次的图；步骤条回到属性/表单页再切回来也不该丢。

7. 提炼成清单

如果你在自己的工程里碰到类似症状，按这四步走，通常十分钟内能定位：

  1. 先怀疑数据，别怀疑渲染。 SELECT CHAR_LENGTH(列), LOCATE('<', 列) FROM 表 ORDER BY 时间 DESC，和已知正常的样本（官方示例数据、种子数据）横向比。长度掉一个量级 + LOCATE 返回 0，基本就是被清洗了。
  2. 确认 XSS 开关面。 xss.enabled（不配也默认开）、mode（CLEAR 才是削 tag；ESCAPE 会变成 &lt;，VALIDATE 直接抛异常）、block-url（默认 /**）、skip-url。
  3. 找到写入口，精准豁免。 承载标记语言的写接口加 @XssIgnore；能确定字段就写 @XssIgnore({"xxx"})。查询类接口保持受保护。
  4. 闭环验证，别只改不测。 加完注解重新保存一次，再跑第 6 节那条 SQL：first_lt 回到 1、len_xml 回到上万，并到「模型设计」列表点「设计」确认画布真的出图。XSS 配置 yml 和 Nacos 各有一份，换环境极易漏配，只有验证能兜住。

另外值得记一笔的方法论：跨工程/异构工程合并代码时，注解、配置驱动的开关这类「不在功能主干上」的东西最容易整批丢失。 对比时不要只 diff 方法体，也要 diff import 区和注解行。
