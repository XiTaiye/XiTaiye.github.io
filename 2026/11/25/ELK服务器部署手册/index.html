ELK服务器部署手册：离线镜像 + HTTPS/mTLS + BladeX 日志接入

关键词： ELK 9.5.5 三件套 · docker save/load 离线导入 · elasticsearch-certutil 自签证书 · bootstrap.elastic.password · logback LogstashTcpSocketAppender

形态一句话：单机 Docker Compose，Elasticsearch / Kibana / Logstash 9.5.5（三者必须同版本），认证 + TLS 全开，镜像走离线导入（服务器不联网）。

0. 拓扑与端口

组件 容器名 宿主机端口 协议 暴露范围
Elasticsearch rixin-elasticsearch 9200 HTTPS + 认证 仅内网 / 运维机
Kibana rixin-kibana 5601 HTTPS + 登录 仅内网 / 浏览器侧
Logstash rixin-logstash 9000 TCP 明文（见 §9.2） 仅白名单应用服务器
Logstash API rixin-logstash 9600 HTTP 无认证 仅 127.0.0.1

数据流：api (logback LogstashTcpSocketAppender) → Logstash:9000 → Logstash → ES:9200 (HTTPS/mTLS 免, 证书校验 full) → Kibana。

与本地 Windows 的差异：

项 本地 Windows Linux 服务器
日志入口端口 9700（9000 撞 Hyper-V 保留段 8948-9047，bind 被拒） 9000（Linux 无保留段问题）
安全 xpack.security.enabled=false 认证 + TLS 全开
密钥存放 ~/.rixin-elk/kibana.key，由 start-elk.sh 注入 /opt/rixin-elk/.env（目录不在 git 仓库内）
镜像来源 docker.1ms.run / docker.m.daocloud.io 在线拉 联网机 docker save → scp → docker load
vm.max_map_count Docker Desktop 默认已 262144 必须自己写 sysctl 并持久化

1. 前置条件

项 要求
OS CentOS 7.9+ / Rocky 8+ / Ubuntu 20.04+，内核 ≥ 3.10
CPU / 内存 ≥ 4 核 / ≥ 8GB 可用（三件套常驻约 3.5GB，ES 堆另留 mmap 余量）
磁盘 ≥ 60GB 独立数据盘，日志索引按保留期估算（见 §10.3）
Docker 24.x+，Compose v2 插件（docker compose version 可用）
时钟 必须 NTP 同步 + 时区 Asia/Shanghai（否则按天索引会早一天，见 §11）
用户 部署操作用 root 或 docker 组用户；容器内 ES/Logstash/Kibana 均以 uid 1000 运行

检查一遍：

SELinux enforcing 且数据盘用 bind mount 时，挂载目录需加 :z 后缀或 chcon -Rt svirt_sandbox_file_t；本手册默认用命名卷，可跳过。

5. 证书制作

SAN 必须覆盖所有访问方使用的名字，这是后面 ssl_verification_mode => full 与 Kibana 证书校验能否通过的唯一变量。先确定访问名清单：Docker 网络别名 elasticsearch、容器名 rixin-elasticsearch、服务器内网 IP、运维机里 curl 用的主机名。

7. 启动与账号初始化

9.2 app → Logstash 这段要不要 TLS

logback-*.xml 里没有 <ssl> 配置块（已 grep 确认），所以开箱只能明文 TCP。生产上建议按「网络隔离替代加密」处理：9000 只对应用服务器 IP 白名单放行、日志内容不落敏感字段。

确实需要这段也加密时，改动分三处，且不属于开箱配置，需按 logstash-logback-encoder 版本文档核对元素名：

  1. Logstash input 换成 tcp { port => 9000 codec => json_lines ssl_enable => true ssl_cert => "/certs/kib.crt" ssl_key => "/certs/kib.key" }（证书 SAN 要覆盖应用访问 Logstash 用的主机名）。

10.5 升级与证书到期

  • 三件套版本必须一致，Kibana 版本不能低于 ES，否则 Kibana 直接拒绝启动。
  • 升级顺序：docker compose stop kibana logstash → 换 ES 镜像 tag → 起 ES 并等 healthy → 换 Logstash/Kibana tag → 全量起。跨大版本先跑 _migration/deprecations 检查。
  • 升级前必做快照（§10.4）。
  • 节点证书 --days 820，到期前替换：重跑 §5（instances.yml 里 IP 若有变动必须一起改），再 docker compose restart elasticsearch kibana logstash。CA 设的 1825 天，换 CA 要同步替换三处 ca.crt 并重新导入系统信任。

11. 故障速查

现象 根因 处理
ES 容器反复重启，日志 max virtual memory areas vm.max_map_count [65530] is too low 宿主机内核参数 §3 sysctl；Docker Desktop 上无需管，Linux 必配
Try to increase the limit on number of open files 容器 ulimits compose 的 ulimits.nofile（§6.2 已带）
failed to copy: invalid input: magic number mismatch 镜像站该 blob 损坏 换源重拉；本地实测 docker.1ms.run 的 ES 9.5.5 坏、docker.m.daocloud.io 可用；离线场景就是重新 save
ports are not available ... bind: An attempt was made to access a socket in a way forbidden 仅 Windows Hyper-V TCP 保留段（8948-9047、5041-5140） Linux 不会出现；本地才把入口挪到 9700
Kibana 弹窗 500「无法检索检测引擎权限」+ 400「无法检索列表权限」 缺 xpack.encryptedSavedObjects.encryptionKey .env 的 KIBANA_ENCRYPTION_KEY（§6.1），Kibana 9 即使关安全也强制要求
Kibana 起不来，日志 Unknown credential / Invalid API key or credentials kibana_system 密码未重置或与 .env 不一致 重跑 §7 的 kibana_system/_password，再 docker compose restart kibana
§7.3 的 bootstrap OK 打印不出来，curl 一直 401 加了 bootstrap.elastic.password 但没 restart（它只在启动时读取）；或 elastic 已坐实后仍把 bootstrap 当新凭据用 重跑 docker compose restart elasticsearch；坐实之后一律用 .env 里的真实口令
docker compose up 直接报 KIBANA_ENCRYPTION_KEY is missing 或空值 没在 /opt/rixin-elk 目录执行，.env 未被加载 cd /opt/rixin-elk 后再执行，或 docker compose --env-file /opt/rixin-elk/.env ...
Logstash 日志 Received successful response: 401 / authentication error rixin_logstash 密码或角色权限不足 核对 .env 与 §7；角色必须含 create_index + write
Logstash 报 SSL 相关 certificate verify failed / hostname mismatch 证书 SAN 不含访问用的主机名/IP 在 instances.yml 补 SAN 重新签发（§5），这是唯一变量
ES 返回 flood_stage disk watermark exceeded、写入全断 磁盘水位触发只读 §10.3
应用日志正常但 ES 无新增 ① 9000 网络不通（安全组）② VM 参数没加或没完整重启 ③ -D 写在 -jar 之后 逐条对照 §9.1
索引日期比北京时间早一天 容器 TZ 未设，%{+YYYY.MM.dd} 用 JVM 默认时区 compose 三处 TZ=Asia/Shanghai（§6.2）
大量日志 traceId 为空 非 HTTP 请求线程（启动 main、@Scheduled、MQ 消费、自建线程池）本就不在 LogTraceFilter/LogTraceAspect 覆盖范围 属预期，不是故障；需要时按线程补 LogTraceUtil.insert() 或给线程池加 TaskDecorator 传 MDC
curl 带中文条件报 Invalid UTF-8 middle byte Windows 控制台码页 Linux 无此问题；断言尽量用 ASCII 字段
Discover 空但 ES 有数据 时间字段不是 @timestamp、时间范围太窄、或数据视图未建 §8 末尾重建数据视图，并把时间范围拉到 Last 15 minutes

附：部署完成后自检清单

  • docker compose ps 三件全部 healthy/Up
  • 不带认证访问 9200 返回 401（证明认证真的生效）
  • http://<IP>:5601 打不开，只有 https:// 可访问
  • 9600 在服务器上 curl http://127.0.0.1:9600 通、从别的机器不通
  • 9000 安全组只放行应用服务器 IP
  • 冒烟日志在 Discover 可检索，中文不乱码
  • date 与容器内 docker exec rixin-logstash date 一致
  • 快照仓库注册成功且已有首个快照
  • /opt/rixin-elk/.env 权限 600、ca.key 已移出服务器
